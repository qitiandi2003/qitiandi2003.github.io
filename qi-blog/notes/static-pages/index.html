旧博客旁边的静态站

旧文章的 URL 属于 Hexo，新手记由 C++ 生成。两个静态站共用一个域名时，图片、正文和搜索结果各自该从哪一级目录找？

Qi2026-11-26约 3 分钟

旧地址也是文章的一部分

翻看 2023 年 11 月的仓库快照，根目录已经有 index.html、按年月排列的归档，以及两篇文章各自的 HTML。首页标出了 Hexo 7.0.0。Hexo 的 generate 命令会生成静态文件，这份快照保存的正是浏览器能直接打开的页面和资源。

新手记采用独立的 qi-blog/ 目录，旧文仍在 2023/11/04/ 下面。可以从个人站根地址点一篇旧文，再直接打开新站某篇手记的深层链接，核对两边的入口。只在新首页里点一圈，容易漏掉旧书签。

一份文章生成哪些文件

Qi‘blog 的初版把内容放在 _qi-blog/articles/，每篇用 JSON 保存标题、摘要、正文小节和来源。C++17 生成器读取文章，写出首页、每篇的详情页、关于页和搜索索引。正文直接进 HTML，浏览器不执行脚本也能读文章。

搜索框读取另一份较小的数据，只需要文章标识、标题、摘要、主题和关键词。同一轮生成同时写正文与索引，可以避免改了标题却仍只能搜到旧名字。初版提交中的生成器还显式列出了七篇文章的顺序，仓库里多一个 JSON 文件本身并不会自动出现在那个版本的首页上。

站在文章页上检查路径

首页与 notes/<slug>/ 里的文章页处在不同深度。例如从文章页引用站内资源，../../assets/site.css 会回到新站的 assets 目录。直接写成域名根目录下的 /assets/site.css，浏览器就会到旧站所在层级找样式。

出站前从实际的子路径打开一篇详情页，核对样式表、封面、搜索结果的目标和回首页的链接。GitHub Pages 支持从指定分支和目录发布。提交包含生成结果后，还要从公开地址读回页面，才能知道访客实际拿到的是哪一版。
