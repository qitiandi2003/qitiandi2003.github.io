为一次网络配置变更写回归测试

从一份包含旧设置的小样本出发，测试改动范围、重复运行和恢复后的内容。

Qi2026-11-26约 2 分钟

造一份足够小的旧配置

公开仓库 ssh-vpn 的配置测试在临时目录里建立样本文件，再比较处理前后的内容。这个方法也适合普通网络客户端的设置迁移。例如把已经过期的连接选项、仍需保留的超时设置和注释放在同一份测试输入里。

先写下迁移后的期望文本。如果配置是 JSON，还要把结果交给解析器重新读取。一行目标设置消失，并不能证明剩下的逗号、引号和层级仍然有效。

第二次执行，容易暴露备份问题

在同一份样本上连续运行两次，观察第二次是否继续改写已经正确的内容。尤其要检查最初的备份。若第二次运行覆盖了第一次保存的原件，当前配置可能仍然正常，恢复时却会只退回到中间状态。

再给测试加一份旧格式配置。读取、迁移、保存、重新读取，分别验证原有选项值和新字段的默认值，能把“文件写得出来”落实到“旧用户的数据还能读”。

从程序实际获得的设置验收

当客户端从启动环境和配置文件两处读取选项时，磁盘文件的变化只说明做完了一半。让一个最小测试进程按照正常入口启动，记录最终采用的非敏感选项。这样能区分迁移程序改错位置，还是后续加载覆盖了它。

最后执行恢复，把文件与最初的样本逐一比较。原件完整、无关设置保留、重复运行结果一致，这三项可以直接写成 C++ 测试断言，之后由 CTest 在每次修改时重跑。
